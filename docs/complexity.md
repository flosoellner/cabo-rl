# Cabo info-set complexity: first real numbers

Generated by [`python/cabo_rl/enumerate.py`](../python/cabo_rl/enumerate.py). Replaces the earlier hand-wavy estimate ("probably somewhere between Limit Hold'em and Dou Dizhu") with actual measured/computed numbers. Reproduce with:

```bash
cd python && source .venv/bin/activate && PYTHONPATH=. python cabo_rl/enumerate.py
```

## Methodology and its known limitation

An **information set** is everything a player can distinguish about the true game state from their own observations: their own known card values, the public discard pile, the public hand-size of the opponent, and the size (not contents) of the draw pile. Two different true deals that look identical under this description belong to the same information set.

**The info-set key used everywhere below is coarse**: it does not yet track *which specific position* a peek/spy/blind-swap targeted, even though that targeting is itself public information (the opponent-modeling design notes for this project depend on exactly this kind of signal — "spied position 3, then didn't blind-swap it"). Every count below is therefore a **lower bound** on the true, fully-refined info-set count. Refining the key to include per-position action history is a roadmap item (state representation, roadmap step 3), not attempted here.

## 1. Exact enumeration, shrunk 8-card variant (validates the methodology)

An 8-card variant (values `0,1,3,5,7,9,11,13` — one of each power band: 7=peek, 9=spy, 11=swap, plus plain cards — one copy each, hand size 2) was enumerated **exhaustively**: every one of the `8! = 40320` possible deals, branched over every legal action at every decision point, for the first two player-turns.

**Hand-verified base case** (before any action is taken): fixing the starting player's one known card and the discard pile's one known card removes 2 of the 8 values; the other 6 can be in any of `6! = 720` orders across the 6 unseen slots (1 own-unknown + 2 opponent + 3 draw-pile). That predicts **56 info sets × 720 states each = 40,320 total** — and the code reproduces this exactly, which is the actual validation: the info-set-key and counting logic are correct before trusting them on the full game.

| Depth | Whose decision | Deal×path combinations reaching it | Distinct info sets | Info-set size range |
|---|---|---|---|---|
| 0 | starting player, before any action | 40,320 | 56 | 720–720 (uniform, as derived above) |
| 1 | other player, after starting player's full turn | 312,480 | 399 | 120–720 |
| 2 | starting player again, after one full round-trip | 2,412,000 | 11,193 | 6–720 |

The gap between "combinations reaching this depth" and "distinct (info-set, true-state) pairs" is real path convergence (different action histories landing on the same actual state), not an error — e.g. at depth 2, roughly 2.13M of the 2.41M paths converge onto states already reached some other way. Info sets already growing **200×** in two turns on an 8-card toy deck is itself informative about how fast the real 52-card game's tree grows.

## 2. Exact info-set size, real 52-card game (closed-form, not sampled)

A multinomial coefficient over the unseen-card multiset — exact, not estimated.

- **Start of round**, agent's perspective (2 own cards known + the discard pile's starting flip = 3 of 52 revealed, 49 unseen slots — 2 own-unknown + 4 opponent + 43 draw-pile, all order-sensitive): **2.665×10⁴⁷** distinct full deals are consistent with what the agent knows (log₁₀ ≈ 47.4).
  - Restricted to just *the opponent's 4-card hand* (marginalizing out draw-pile order, which doesn't affect the current decision): **38,307** distinct possible opponent hands. This is the more decision-relevant number.
- **Mid-round** (13 cards revealed: the above 3, plus 2 more of the agent's own cards peeked, 2 of the opponent's spied, and 6 more cycled through the discard pile; 39 unseen slots left): **4.685×10³⁶** distinct full deals (log₁₀ ≈ 36.7).
  - Distinct possible values for the opponent's remaining 2 *unknown* positions (2 of their 4 already spied): **195**.

Info-set size shrinks by about 11 orders of magnitude over the course of one round as cards get revealed — the earlier "10³–10⁶" hedge undersold the start of a round enormously if draw-pile order counts as part of the true state (it does, since it determines what gets drawn later), but lands close to that range once attention narrows to just the opponent's remaining unknown hand (195, 38307) — which is arguably the more decision-relevant quantity day to day.

## 3. Monte Carlo info-set count, real 52-card game (lower-bound sampling estimate)

3,000 simulated rounds, both seats playing `RandomPolicy` (legal-but-unstrategic, exercises all rule branches — not meant to resemble real play), counting distinct coarse info-set keys actually visited:

| Rounds simulated | Distinct info sets seen (human) | Distinct info sets seen (agent) |
|---|---|---|
| 100 | 983 | 966 |
| 500 | 4,831 | 4,816 |
| 1,000 | 9,860 | 9,807 |
| 2,000 | 19,571 | 19,522 |
| 3,000 | 29,495 | 29,450 |

Growth is close to linear in rounds simulated with no sign of saturating — expected, since the true info-set count is astronomically larger than anything 3,000 rounds could visit (consistent with part 2's per-decision-point numbers above). This confirms the count is large enough that **exploitability-based evaluation, not exhaustive solving, is the right approach for the full game** — matching the project's original evaluation-methodology conclusion, now with real supporting numbers instead of an analogy to poker/Dou Dizhu.

## Bottom line

Cabo's full-game info-set count is not something this or any near-term enumeration will pin down exactly — the combinatorics are in Dou-Dizhu-to-Mahjong territory once draw-pile order is counted, and still in the tens-of-thousands-per-decision range even when narrowed to just "what could the opponent's hand be." That's consistent with going straight to NFSP/Deep CFR/ReBeL rather than any exact-solving approach, and with treating exploitability (roadmap step 5) as the evaluation metric rather than trying to compute a true value function.
